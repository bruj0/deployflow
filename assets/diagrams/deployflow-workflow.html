How an application reaches a server

Four lanes, one direction. The agent writes, you approve, appctl delivers, and the guest proves the service answers before the run is called done.

THE HEADLINE

The green play is not the proof

A run is not done when the playbook exits zero. It is done when the service answers a request — so the checks live in the role, and they run after every install.

One owner per step

  • You ask, the agent writes, appctl delivers
  • Crossing a lane is a handoff, never a shared step
  • A refusal names the fix and goes back to the agent

Run it twice

The second appctl install reports changed=0. That is the proof the run is repeatable rather than reinstalling itself.
