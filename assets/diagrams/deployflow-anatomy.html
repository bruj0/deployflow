What an application looks like in the repository

Adding an application touches two places and nothing else: one entry in app.yaml, and one directory under apps/. Every box below carries the file that holds it.

THE HEADLINE

Two files, one target

One entry in app.yaml and one directory under apps/. Nothing in common/ or src/appctl/ changes, because the framework never names an application.

The checks are the contract

  • They live in the role's own tasks/main.yml
  • They run after every install
  • Only the application knows what "working" means

One target ships today

proxmox_lxc is implemented. docker_vm and vm are named so a manifest can ask for them and get a clear answer instead of a failure.
